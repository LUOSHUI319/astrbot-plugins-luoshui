# 回复延时

给机器人加一点「迟疑感」：每条要发出去的回复，先在配置的区间里随机抽一个秒数，抽到多少就延时多少秒再发。

## 效果

1. 大模型回复准备好了，不立刻发，先抽一个 5~20 之间的数。
2. 抽到 15 就等 15 秒再发；抽到 7 就等 7 秒再发。
3. 一次回复里有好几条消息（框架的分段回复）时，每一条各抽各的，互不影响。

## 实现方式

在 `on_decorating_result`（发送消息前）钩子里，把当前消息事件对象的 `send` 方法替换成带随机延时的包装函数。

- 事件对象每条消息独享，替换实例属性不会影响别的会话；
- 框架分段回复时是多次 `event.send` 调用，所以天然做到一条一抽；
- 如果只在钩子里 `sleep` 一次，只会把整条回复整体推后，消息之间的间隔就没了。

## 配置

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| 启用插件 | 总开关 | 开 |
| 最小延时（秒） | 随机区间下限 | 5 |
| 最大延时（秒） | 随机区间上限 | 20 |
| 只对大模型回复生效 | 关掉后插件、指令回复也会延时 | 关 |
| 私聊生效 / 群聊生效 | 生效范围 | 都开 |
| 生效平台 | 平台适配器名，留空为全部 | aiocqhttp |
| 输出抽到的延时日志 | 调试用 | 关 |

## 已知不生效的场景

- 流式输出（streaming）。
- tool 中的 `send_message_to_user`：它绕过当前事件对象直接下发，拿不到这里打的补丁。
